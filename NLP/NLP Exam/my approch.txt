RETRIEVAL LAYER - Hybrid Search  (DONE)
- WHY: BM25 (keyword) catches exact rare terms (e.g. "A350"); dense (semantic) catches meaning/synonyms.
  Each is blind where the other is strong -> combine them = better retrieval.
- Built BM25 index over the 200 docs (BM25Okapi, texts lowercased + split = tokenization).
- Step 1: bm25_scores  = bm25.get_scores(query tokens)        -> keyword score per doc
- Step 2: dense_scores = cosine_similarity(query_emb, doc_emb) -> semantic score per doc
- Step 3a: normalize both to 0-1 (min-max) because they are on different scales.
- Step 3b: combined = alpha*dense_norm + (1-alpha)*bm25_norm   (alpha = balance knob, 0.5 = equal)
- Step 4: rank by combined score -> np.argsort(combined)[::-1][:k] -> top-k docs.
- TESTED on "Lufthansa A350 fleet order": top result = exact "A350 (On order)" doc (score 1.000). Good.
- Hybrid vs pure semantic were NEARLY IDENTICAL here (only #2/#3 swapped).
  LESSON: hybrid is a SAFETY NET -> it helps mainly when semantic MISSES an exact rare term;
  on easy queries semantic already works so hybrid changes little (and does no harm).
- TODO (small): wrap Steps 1-4 into one reusable function hybrid_search(query, k, alpha) for the dashboard.

task 4 - Strategic Intelligence Engine     [notebook: Strategic Intelligence Engine.ipynb]
- GOAL: add INTELLIGENCE to each doc = two labels:
    category  = opportunity / risk / trend            (zero-shot, facebook/bart-large-mnli)
    sentiment = negative / neutral / positive (3-class, cardiffnlp/twitter-roberta-base-sentiment-latest)
- NOTE: started with binary distilbert-sst-2 (News Analyst tool) but it has NO neutral class + was trained on
  movie reviews -> it FORCED neutral listing pages into pos/neg with high (but unreliable) confidence.
  Switched to a 3-CLASS model (negative/neutral/positive) so neutral factual pages are correctly "neutral".
- WHY zero-shot: no labeled training data; define labels at runtime; model judges fit (NLI entailment).
  HOW it scores: each label becomes a hypothesis "this text is about {label}"; model scores how much the
  text (premise) ENTAILS it; scores normalized; highest wins. (bart-large-mnli = trained on NLI.)
- Both tools come from Agents.ipynb: zero-shot = Support Agent (intent), sentiment = News Analyst Agent (Ex.2).
- Framing = an "Analyst Agent" (perceive doc -> reason classify+sentiment -> act tag doc). Feeds the CEO Agent (Task5).
- Ollama is NOT used here -> small fast models for bulk labeling; Ollama (the reasoning LLM) is for Task 5.
- RESULTS (all 200 docs):
    sentiment -> neutral 118, positive 55, negative 27  (big neutral chunk = listing/factual pages, as expected)
    category  -> trend 100, risk 87, opportunity 13     (opportunity rare: explicit opp framing seldom in short snippets)
  Confidence on generic docs is lowish (0.4-0.6) because the 3 labels overlap and snippets are short -> OK,
  category is a ROUGH sort; the Task 5 LLM does the real reasoning.
- SAVED to lufthansa_labeled.json (200 docs, each has category + sentiment).
- KNOWN ISSUE (deferred to cleaning pass before dashboard): 3 TEXT duplicates survived URL-dedup
  (different URLs, same text -> URL-uniqueness != content-uniqueness). Fix = dedup by text + rebuild Chroma/BM25.
- SUBTYPES (opportunity/risk/trend each have examples in the brief): those are EXAMPLES not required sub-labels.
  Keeping 3 main categories (robust, higher confidence). Subtypes = OPTIONAL; can demo live with a 2-level classifier
  (dict category->subtypes, 2nd zero-shot on subtypes[category]). Drawbacks of doing it now: lower accuracy (errors cascade),
  ~2x runtime, more code, not required -> keep as on-demand demo only.
- Reusable wrapper analyst_agent(doc) (perceive->reason->act) available for the dashboard to label new docs on the fly.
- Data note: models are English; my corpus is English (English DDGS queries), so safe. Non-English would be unreliable.
- text[:512] used for sentiment (BERT/RoBERTa 512 token limit).
